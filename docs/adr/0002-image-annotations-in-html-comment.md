# 画像の注釈は HTML コメントに JSON で持ち、MD は焼き込み画像を参照する

画面キャプチャに矢印やコメントを重ねたい（Excel で図形を置く代わり）。注釈は MD の画像の直後に `<!-- annotate {"src":"元画像","size":[w,h],"items":[...]} -->` として書き、画像のリンク自体は注釈を描き込んだ `<元の名前>.annotated.png` を指すことにした。こうすると GitHub など他のビューアでも注釈入りの画像が見え、このアプリではコメントを読んで元画像の上に SVG で描き直すので、何度でも編集できる。

## Considered Options

- **画像に直接描き込むだけ**: どこでも見えるが、あとから直せない（元画像が残らない）
- **HTML の絶対配置（`position:absolute`）で文字を重ねる**: 座標が px 固定で、表示幅やズームが変わるとずれる。他のビューアでは style が消されることがある
- **注釈を別ファイル（JSON）に持つ**: MD を移動・コピーしたときに注釈が離れやすい
- **元画像を参照し、注釈はこのアプリでだけ見せる**: 他のビューアでは矢印が見えない

## Consequences

- 焼き込み画像は、適用した時点では書き出さず、貼り付け画像と同じく MD を保存したときに書き出す（Excel のように、保存前の MD や貼り付けたばかりの画像にも注釈でき、保存せずに閉じればディスクに何も残らない）。元画像の隣にファイルが増える。名前は最初の適用で空いている `<元の名前>.annotated.png` / `.annotated-2.png` … を選び、以降は MD に書かれた名前を使い続ける（同じ元画像を複数の箇所・複数の MD で注釈しても、互いに上書きしないため。MD の名前を入れる案は、MD の名前を変えると古いファイルが残るので採らなかった）
- 注釈を全部消すと元画像の参照に戻すが、焼き込み画像のファイルは消さない（ほかから参照されていないことを確かめられないため）
- 座標・線の太さ・文字の大きさは元画像のピクセル単位。元画像を大きさの違う画像に差し替えると、次に開いたときに同じ割合で引き伸ばす
- コメントは DOMPurify に消されるので、Markdown の解析時に画像の `data-annotate` 属性へ移してから描く。JSON の `--` と `<` `>` は `\u` エスケープにする（コメントの終端と、属性の検査を避けるため）
