# ショートカットは JS で一元処理し、ネイティブのメニューバーにはキーを表示するだけにする

ツールバーのボタンを Windows 標準のメニューバー（Tauri 2 の Menu API）へ移した。Tauri のアクセラレータ（メニューに登録するショートカット）は、WebView2 にフォーカスがあるとホストに届かず発火しない（wry issue #451、未解決）。そこで、キー処理は従来どおり `src/main.ts` の keydown ハンドラだけに置き、メニュー項目には `"保存\tCtrl+S"` のように文字列で表示だけ付ける。メニューのクリックも同じ JS の関数を呼ぶので、キーとメニューのどちらから実行しても動作は変わらない。PDF プレビュー中の Ctrl+S のように、画面の状態で動作が変わるショートカットもそのまま扱える。

## Considered Options

- **アクセラレータを登録する**: エディタにフォーカスがあると効かない。メニューバーにフォーカスがあるときだけ効く、という分かりにくい動作になる
- **Rust で WebView2 の `AcceleratorKeyPressed` を拾ってメニューに回す**: キーはネイティブで完結する。ただし、状態で変わる動作の判定を Rust と JS の両方に持つことになる

## Consequences

- 「編集」メニューの元に戻す・切り取り・コピー・貼り付けなどは Tauri の既定項目（キーを合成して送る）を使う。合成されたキーは JS とエディタにそのまま届く
- Alt+F などのメニューを開くキーも、エディタにフォーカスがあると Windows に届かない。そのため JS で拾い、Rust のコマンドから `WM_SYSCOMMAND` / `SC_KEYMENU` を送ってメニューを開く
- 後から `setAccelerator` を呼ぶと、表示用の `\t` と重なって表示が崩れる。この方式をやめるときは、表示文字列からも `\t` 以降を外す
