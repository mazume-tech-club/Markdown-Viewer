# 中継サーバーは作者が運営せず、利用団体が自分の Cloudflare に置く

インターネット越しの共同編集には、ホストと参加者の間で変更を受け渡す中継サーバーがどうしても要る。作者のアカウントに置くと、誰でも作者の費用で使えてしまう。そこで、中継サーバーのソース（Cloudflare Worker + Durable Object）を同じリポジトリで配り、共同編集を使いたい団体（利用団体）が自分で Cloudflare を契約して置くことにした。費用は利用団体が持ち、作者はサーバーの費用も運用も負わない。変更はエンドツーエンドで暗号化するので、中継サーバーは中身を読めず、何も保存しない。

## Considered Options

- **P2P（WebRTC）**: 会社のネットワークでは UDP が止められることが多く、結局 TURN という中継が要る。ブラウザ以外から WebRTC を使った実績も少なく、実装が重い
- **作者が中継サーバーを運営する**: 利用者を契約者だけに絞る仕組みと、費用の負担を作者が抱えることになる

## Consequences

- 共同編集プラグインには、利用団体の中継サーバーの URL を設定する欄が要る。参加者は、ホストの利用団体に認められていないと、その中継サーバーを使えない
- 中継サーバーは各利用団体のアカウントで別々に動く。更新するときは、利用団体がそれぞれ置き直す必要がある
- Workers の無料プランだと、1 日の上限に達すると翌日 9:00（日本時間）まで使えなくなる。本格的に使う利用団体には月 $5 の有料プランを勧める
